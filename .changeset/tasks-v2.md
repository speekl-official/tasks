Implemented the `.tasks` convention v2. A task is now a directory with a `task.md` manifest and a workspace (`state.md`, `design.md`, `plan.md`, `log.md`), nested at any depth; ids are paths and the `id` and `phase` fields are gone. The lifecycle is fixed (`BACKLOG`, `TODO`, `IN_PROGRESS`, `PAUSED`, `DONE`, `CANCELLED`) with a transition table, authorization, `--force`, and containment cascades; `state.md` is required to pause or hand off. Added priorities, assignees, finish gates (`finishes_after`), sessions with heartbeats and takeover of orphaned claims, `projects:` aliases with writes into listed trees, one lock per tree, `index.md` in place of `_index.md`, archive merge with `purge` and `delete`, and the commands `schedule`, `defer`, `pause`, `done`, `cancel`, `reopen`, `handoff`, `assign`, `unassign`, `priority`, `after`, `log`, `state`, `resume`, `mine`, `tree`, `archive`, `restore`, `purge`, `heartbeat`, `session-end`, `session-check`, `migrate` and `hooks install`. Removed `status` and the configurable statuses, roles and transitions. A v1 tree is refused by every command except `migrate`, which upgrades it once. The JSON shapes changed: task objects carry derived conditions, collections carry `scope`, `projects`, `malformed` and `unavailable`, and `move` reports the trees it skipped. `archive --resolved-before <when>` and `--all-resolved` archive every resolved subtree older than a threshold in one call, skipping and listing the ones open tasks reference, and `archive_resolved_after_days` in `config.yml` makes `validate` report the ones still live. `actors:` in `config.yml` lists who tasks may be assigned to, each with a line on who they are: `assign`, `handoff`, `new --assign` and `--as` then refuse other names, `validate` warns `unknown-actor` for an open task whose assignee or claimant is unlisted, and `tasks actors` shows the roster with each actor's open tasks. An agent acts as `agent` by convention: the harness hooks export the name, and the skill sets it on every command without them, so a task assigned to `agent` reaches the agent either way. `init --actors [<names>]` writes the roster at once, and the scaffold's commented `actors:` example names the actor `init` resolved and `agent`.
