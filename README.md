# tasks

Monorepo for **`@speekl/tasks`** — a local, git-versioned task manager for AI
coding agents.

Task state lives in a `.tasks/` directory in your repo as markdown with YAML
frontmatter: readable by a human, parseable by an agent, versioned by git. No
server, no account, no network.

Documentation and the normative `.tasks` spec: **[agenttasks.dev](https://agenttasks.dev)**.

`tasks init` also installs an [agent skill](https://agentskills.io) into
`.claude/skills/tasks/`, so an agent arriving in the repo discovers the
convention without being told about it. The skill source lives at
[`packages/tasks/skill`](./packages/tasks/skill) and ships inside the npm
package.

| Package                              | Description                                                        |

## Getting started

Development needs Node 22.13+ (what pnpm 11 requires); the published CLI itself
runs on Node 20+.

```sh
pnpm install
pnpm build          # -> packages/tasks/dist/index.js
pnpm test
```

Try the CLI without installing it globally:

```sh
cd /some/project
node /path/to/tasks/packages/tasks/dist/index.js init
```

## Scripts

Run from the repo root; turbo fans these out across the workspace.

| Script                  | Purpose                                                                 |
| ----------------------- | ----------------------------------------------------------------------- |
| `pnpm build`            | Build every package.                                                    |
| `pnpm test`             | Run all test suites.                                                    |
| `pnpm lint`             | Lint every package.                                                     |
| `pnpm check-types`      | Typecheck without emitting.                                             |
| `pnpm format`           | Format with Prettier.                                                   |
| `pnpm changeset`        | Record a user-facing change for the next release.                       |
| `pnpm version-packages` | Consume changesets: bump versions and write `CHANGELOG.md`.             |
| `pnpm release:check`    | Full pre-release gate: lint, types, tests, build, and a packed tarball. |

## Contributing

### When you need a changeset

Versions and `packages/tasks/CHANGELOG.md` are generated by
[Changesets](https://github.com/changesets/changesets), not hand-edited. Any
change that a user of `@speekl/tasks` could notice needs a changeset in the
same PR as the change itself:

```sh
pnpm changeset
```

Pick the package, pick the bump, and write the changelog line — one sentence,
in the past tense, describing what changed for the user. That writes a markdown
file under `.changeset/`; commit it alongside your code.

**Needs a changeset:** new or removed commands and flags, changed output, JSON
or exit-code changes, changed `.tasks/` file conventions, bug fixes, and
dependency bumps that reach users.

**Does not:** tests, refactors with no behavior change, CI config, internal
docs, and edits to this README.

Pick the bump by what breaks:

| Bump    | When                                                                                       |
| ------- | ------------------------------------------------------------------------------------------ |
| `patch` | Bug fixes and internal changes users can see but don't have to act on.                     |
| `minor` | New commands, flags, or output that existing usage keeps working with.                     |
| `major` | Anything that breaks an existing invocation, JSON shape, exit code, or on-disk convention. |

Because agents branch on the JSON shape and exit codes, treat those as public
API: changing one is a `major`, not a `patch`.

Releasing then consumes every accumulated changeset at once — see
[`PUBLISHING.md`](./PUBLISHING.md).
