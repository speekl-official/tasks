title: Configuration
description: The keys of config.yml, with their types and defaults.

`.tasks/config.yml` is REQUIRED and MUST carry `version: 2`. All other keys are OPTIONAL.

```yaml
version: 2
scope: auth-rework               # default query scope, a group or task path
session_timeout_minutes: 30      # heartbeat age after which a claim is orphaned
archive_resolved_after_days: 30  # resolved this long ago and still live: reported
actors:                          # who tasks may be assigned to
  alice: maintainer; approves plans and does releases
  agent: the coding agent
  codex: { type: agent, description: a second coding agent }
docs:                            # where the project's documentation lives
  engineering: docs/engineering
  api: ../api-docs
custom_fields: [review_ticket]   # the project's own frontmatter keys, checked once listed
projects:                        # aliases for sibling trees
  backend: ../backend
  cli: ../arkveil-cli
```

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `version` | `2` | — | Convention version; REQUIRED. |
| `scope` | path | none | Default scope for `list`, `ready`, `tree` and `claim --next` when the caller gives none; while it applies, these keep to the local tree. Never restricts addressing by id, gate resolution or validation. |
| `session_timeout_minutes` | integer ≥ 1 | 30 | Liveness threshold for claims. |
| `archive_resolved_after_days` | integer ≥ 1 | none | Resolved subtrees whose root's `updated` is older than this, and that `archive --resolved-before` would take (no open task references them from outside), are reported by validation as not yet archived; `archive --resolved-before` without a value uses it. |
| `actors` | map actor → one-line description or `null`, or `{ type, description }` | `{}` | The roster: who tasks may be assigned to, each with a line on who they are and a `type`, `person` or `agent`; a bare entry is a person, the name `agent` an agent. See [Actors](/docs/spec/sessions#actors). |
| `docs` | map name → relative path | `{}` | Where the project's documentation lives, by name: the locations an agent brings up to date before `done`. See [Documentation](#documentation). |
| `custom_fields` | list of key names | `[]` | The frontmatter keys of the project's own that manifests may carry beside the defined ten ([Task file](/docs/spec/task-file#serialization)); a name is letters, digits, `_` and `-`, starting with a letter or `_`, and not a defined field. Once any is listed, validation reports a key outside the list as an error and a listed one not at all; empty or absent, an undefined key is a warning. |
| `projects` | map alias → relative path | `{}` | See [Projects](/docs/spec/projects). |

Unknown top-level keys MUST be rejected as a usage error. Invalid YAML, or a document that is not
a mapping, MUST fail as a usage error naming the file. There are no `statuses`, `roles` or
`transitions` keys: the lifecycle is fixed by this specification.

A non-empty `actors` is a roster. An actor named for someone else — by `assign`, `handoff`,
`new --assign`, or `--as` on a command that opens the tree — MUST be listed, or the command
fails as a usage error naming the listed actors, which no force lifts; the roster of the tree
that holds the task judges `assign`, `handoff` and `new --assign`, the local tree's judges
`--as`. The identity a command resolves for itself MUST NOT be refused for being unlisted, and
SHOULD be diagnosed. Validation reports an open task whose `assignee` or `claimed_by` is
unlisted. Keys match the actor pattern and MUST be read as the names written (a name YAML would
take for a number or a boolean, `007` or `True`, is refused unquoted); a bare name carries
`null`. Empty or absent, the roster constrains nothing.

## Documentation

`docs` names where the project's documentation lives: each key matches `^[a-z0-9][a-z0-9-]*$`,
like a project alias, and maps to a path relative to the project root — a directory or a file,
inside the repository (`docs/engineering`) or beside it (`../api-docs`). An absolute path MUST be
rejected as a usage error, as a project path is. The locations constrain no command: `resume`
reports them with whether each exists on this machine ([CLI](/docs/spec/cli#commands)),
validation reports an absent one as a warning, and the [agent protocol](/docs/spec/agent-protocol#exit)
says what an agent owes them before `done`. The locations of the tree that holds the task apply.
Empty or absent, the key asks nothing.
